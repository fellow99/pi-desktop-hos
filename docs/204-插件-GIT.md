## 1. 目的

鸿蒙环境**没有 `git`**（toybox 不提供；`git: inaccessible or not found`，能力清单 #17/#18），`git` 全部命令不可用；即使工作区里有仓库，模型也无法做任何版本控制操作。

本设计交付一个 **pi agent 扩展** `harmony-git`，把**纯 JS 的 git 实现 isomorphic-git 1.44.2** 嵌入应用，向模型注册 **21 个 `git_*` 工具** + 1 个凭据管理工具 `git_credentials`，并提供**设备自管的 git 原生凭据文件**管理带账号仓库的用户名/密码。全部操作发生在设备进程内，不依赖任何外部二进制、不需要子进程、不联网安装（`PI_OFFLINE=1`），**不触碰父工程**。

**范围外（明确不做）**：`rebase`（isomorphic-git 无此原语，自研等于重写提交重放引擎）、`blame`、`grep`（已有 `grep` 工具）、SSH 传输（isomorphic-git 无 SSH 客户端，§3 F2）、SHA-256 仓库（isomorphic-git 现状仅 SHA-1）。

## 3. 关键事实

| # | 事实 | 含义 |
|---|---|---|
| F1 | isomorphic-git **没有 SSH 客户端**：`git@host:path`/`ssh://` 被改写为 `https://`（丢弃用户名） | 「SSH 密钥」不可交付；仅 HTTPS 用户名/密码凭据 |
| F2 | isomorphic-git **无 `diff`/`show`/`rebase`/`revert`/`blame`/`grep`**；`cherryPick` 无 `reversal` | `diff` 用 bundle 内 `createTwoFilesPatch`；`show`/`revert` 自建；`rebase` 明确不交付 |
| F3 | isomorphic-git 经 `onAuth` 只做 **HTTPS Basic 认证**（`{username,password}`/`{headers}`/`{cancel}`），`onAuthFailure` 可拒绝 | 凭据注入点明确，且仅在服务端要求时才调用 |
| F4 | **isomorphic-git 用 `isPromiseFs()` 判 fs 方言**：无参调用 `fs.readFile()` 看返回是否 promise-like；适配器若同步抛错会被判成 callback 风格 → 11 命令被 `pify` 包成「等回调」永久挂起 | **所有 fs 适配器方法必须声明 `async`**（dsh 真机发现 §3.1-①，原样沿用其修法） |
| F5 | `jiti.import` 能从**扩展目录**解析兄弟 `*.cjs`（bundle）与包 `node_modules`；但 pi-dist 的 `node_modules` **不在** `<pi-agent>/extensions/` 的解析路径上 | 依赖必须随扩展目录自供；故用**单文件 bundle** 而非依赖 pi-dist |
| F6 | 设备**禁 symlink**、资源 copy 物化；目录扩展整树随 `extensions/` 递归拷贝到 `<userData>/pi-agent/extensions/harmony-git/` | vendor bundle 放扩展目录内即可随包落地 |
| F7 | 设备出网可用（#22），但内网明文 `http://` 会让 Basic 凭据 base64 明文过网 | 网络读写链成立；http 风险如实登记并建议 HTTPS |
| F8 | **无逐写审批围栏**；唯一门禁 project trust | 不做假审批；chroot 仅为防逃逸/防误删的防御层 |
| F9 | bundle（esbuild，`node:*` external）本机 Node v24 + jiti 2.7.0 实测可加载、可跑真仓库操作 | 依赖供给路线实证可行，无未知风险 |

## 4. 用户故事

- 作为用户，我希望在对话里直接让模型 clone 一个公开仓库并读懂它，不必先想办法装 git。
- 作为用户，我希望填一次带账号仓库的用户名/密码，之后模型执行 pull/push 不必知道密码、密码也不进对话。
- 作为用户，我希望模型在工作区内自由操作；指向异常路径时得到**清晰报错**而非静默。
- 作为用户，我希望任何失败都**如实说明原因**（缺凭据/认证失败/冲突/越界），而不是假装成功或静默重试。
- 作为用户，我希望知道哪些 git 操作**本平台做不到**（`rebase`），而不是让它悄悄用别的方式代替。

## 6. 方案对比

### 6.1 isomorphic-git 依赖供给

| | **A. 单文件 bundle 入库（采用）** | B. vendored node_modules | C. 运行时安装 |
|---|---|---|---|
| 形态 | esbuild 预打 1 个 `vendor/isomorphic-git.bundle.cjs`（888 KB，含 diff） | `vendor/node_modules/`（56 包 / 8.3 MB） | 运行时 `npm install` |
| 自包含 | ✅ 单文件、零解析风险 | ✅ 但深层解析无证 | ❌ `PI_OFFLINE=1`、npm 僵尸 |
| copy IO / 装配 | 极小，随 extensions 树递归 | 大（数百文件逐次 copy） | 不可行 |
| jiti 解析 | 兄弟文件，已实证 | 深 node_modules，设备无证 | — |
| 升级 | 重跑 bundle 脚本、提交 | 重新物化整树 | — |
| 确定性 | 高（头注版本+sha+命令） | 中 | 低 |

**结论：采用 A**，F9 已实证；B/C 均被平台事实否决或带来无谓风险。

### 6.2 工具粒度

| | **A. 一动词一工具（采用，21+1 个）** | B. 单 `git` 工具 + `command` 枚举 |
|---|---|---|
| 模型可靠性 | 高（按名选工具 + 精确 schema） | 低（大联合 schema，易传错参） |
| 可独立验收 | 是（一个工具一组用例） | 否（耦合单一入口） |
| 上下文成本 | 22 条 schema | 1 条长 schema |

**结论：采用 A**，与工程「一工具一职责」惯例一致，逐操作验收对应关系直接成立。

### 6.3 jsdiff 供给

| | **A. 并入 bundle（采用）** | B. 额外 vendor `diff.js` |
|---|---|---|
| copy/解析 | 零额外文件，单 bundle 自足 | 多一个待解析文件 |
| 维护 | bundle 内一次产出 | 两套产物 |

**结论：采用 A**（D4），`createTwoFilesPatch` 与 git 同 bundle 暴露。

## 8. 仓库根围栏（纯防御，非审批）

1. 每个工具调用先把 `dir` 归一（`path.resolve`，相对会话 cwd）为**仓库根绝对路径**；这是后续全部路径的唯一来源。
2. 适配器内**每个路径** = `join(root, rel)` → `normalize` → **前缀包含校验**；越界（`..` 逃逸、绝对路径、软链指向根外）即拒，不落到 `node:fs`。
3. `dir` 合理性：对照 `PI_HOS_ROOTS`（sandbox/desktop/documents/download），落在预期根之外时给**清晰错误提示**（不静默、不假装审批）。用户目录 OS 未授权时 `EPERM`/`EACCES` 原样归因并提示需系统设置授权后重启（能力清单 A.2 #6）。

**如实声明（与 `harmony-exec` 同级）**：git 仓内写操作**不经过逐写审批**，chroot 只是防逃逸/防误删的防御层；本设计**不提供** dsh 式一次性提权（pi 信任模型无此机制）。

## 9. 凭据流程（替代 dsh 凭据库 + 设置页）

### 9.1 存储（git 原生凭据文件）

路径 = `$PI_CODING_AGENT_DIR/.git-credentials`（设备上 `<userData>/pi-agent/.git-credentials`）。

- **格式 = git 原生**：一行一条带 userinfo 的 URL —— `<协议>://<username>:<password>@<host[:port]>`，与 `git credential-store` 同形；userinfo 百分号编码（口令里 `:`、`@`、`/` 可往返）；可手工编辑、可随配置目录整份拷走。
- **解析容忍**：空行/`#` 注释/非 URL 行/无 userinfo 行一律跳过而不抛错。
- **匹配（对齐 `git credential-store`）**：协议与 host（含端口，大小写不敏感）必须一致；带路径的行按前缀匹配且优先；同分则**文件里靠后的行覆盖靠前的**。
- **写入**：临时文件 + `rename` 原子替换，保留其余行与注释；强制 `0600`；同一 `协议+host+用户名` 视为同一条（替换），同 host 异用户是第二条。**删除**：只删匹配行，删空则删文件。

### 9.2 录入方式（无设置页，用 `git_credentials` 工具）

新增第 22 个工具 `git_credentials`，子命令：
- `set {url, username, password}` → 解析 url 得协议/host，原子写入该文件（**password 绝不回显、不进 details、不进日志**）。
- `unset {url, username?}` → 删除匹配行。
- `list` → 仅回显 `协议://host` 与用户名（**脱敏，不回显密码**）。

模型也可按报错引导直接写该文件。**所有网络工具的参数都不含密码字段**。

### 9.3 运行期认证

```
git 操作需要认证（服务端 401/404 且未带凭据）
   ▼
auth.js：从 URL 取 host → git-credentials.js matchCredential(url)
   ▼
命中 ─► onAuth 返回 { username, password }   明文仅在进程内存
未命中 ─► onAuth 返回 { cancel: true }
        → 工具报错：「该主机未配置凭据：用 git_credentials 设置，或在
          $PI_CODING_AGENT_DIR/.git-credentials 加一行 <协议>://<user>:<pass>@<host>」
        （不抛裸 401；不猜测、不匿名重试）
onAuthFailure ─► 「凭据被拒绝」+ 该文件路径；最多重试 1 次，绝不无限重试
```

- 明文**进不了**对话、日志、`details`：凭据只经 `git-credentials.js` 读取，工具参数无密码字段。
- 无账号（公开）仓库从不触发 `onAuth`，零凭据可完成 clone/fetch/pull/本地全部操作。

### 9.4 身份（`user.name`/`user.email`）

不是密钥，**不进凭据文件**：由 `git_config` 写仓库本地配置；默认占位值 `{ name: 'yourname', email: 'yourname@somehost' }`（**刻意占位，不含真实个人信息**）。

## 11. 三个自建能力（isomorphic-git 缺口）

### 11.1 `show`
读 `readCommit`/`readTree`/`readBlob`/`readTag` 拼装输出：提交元信息（作者/时间/parents/message）+ 变更清单 + 逐 blob 内容。无需新依赖。

### 11.2 `diff`
`statusMatrix` 给变动清单，`readBlob` 取两侧字节，**bundle 内** `createTwoFilesPatch` 产 unified diff。
- `stat` 模式只汇总增/删/改行数；`pathspec` 过滤；含 NUL 字节判二进制，输出 `Binary files a/… and b/… differ`，不做文本 diff。

### 11.3 `revert`（自建，fail-closed）
`cherryPick` 无 `reversal`，算法：
1. `readCommit({oid})`；**恰好 1 个父提交**才继续（不做合并提交反向）。
2. 枚举父提交与目标提交的变更路径（两 tree 对比）。
3. 每个变更路径：把**父提交**内容物化到工作区（父无此路径 → 删除）。
4. `add` 上述路径 → `commit`（消息 `Revert "<原标题>"`）。

**冲突语义（fail-closed）**：第 3 步前先比对工作区该路径 blob oid 与目标提交是否一致，不一致说明工作区已分叉 → **拒绝执行并列出冲突路径**，绝不静默覆盖。

## 12. 错误处理

| 场景 | 表现 |
|---|---|
| 目标目录不是仓库 | 明确报「不是 git 仓库」并建议 `git_init`/`git_clone`，不静默创建 |
| 缺凭据 | §9.2：点名凭据文件路径与可照抄占位行 `<协议>://<user>:<pass>@<host>`，非裸 401 |
| 凭据被拒 | 报「凭据被拒绝」+ 文件路径，最多重试 1 次 |
| 合并/摘取冲突 | `abortOnConflict` 默认 `true`（不污染工作区），报冲突路径，提示可 `git_merge` 中止 |
| `revert` 工作区分叉 | §11.3 fail-closed 拒绝并列出冲突路径 |
| `dir` 越出预期根 | §8 清晰错误，不假装审批 |
| 用户目录 OS 未授权 | `EPERM`/`EACCES` 原样归因，提示系统设置授权并重启 |
| 网络不可达/DNS 失败 | 报主机名与底层错误，不假装成功 |
| non-fast-forward 推拒 | 原样报服务端 `PushResult.error`，**不自动 force** |
| clone 体积/超时 | 报已用时与建议（`depth`/`singleBranch`）；取消经 `signal` 透传 |
| 调用被取消 | 停止执行并交注册表处理取消语义，不当作失败 |

## 15. 约束与已知限制

- **L1 `rebase` 不支持**（F2）：明确报「本平台不支持」，不静默用 merge 冒充。
- **L2 SSH 不可用**：仅 HTTPS 用户名/密码；`git@`/`ssh://` 转 https（丢弃用户名）。
- **L3 依赖体积**：扩展目录新增 bundle ≈ 888 KB（含 diff）。
- **L4 纯 JS 性能**：clone 大仓库慢于原生 git；提供 `depth`/`singleBranch`/`noTags` 缓解。
- **L5 无逐写审批**：git 仓内写不经过审批（§8 如实声明，与 exec 同级）。
- **L6 凭据无 UI**：经 `git_credentials` 工具或手编文件管理；无设置页（pi 扩展无挂载点）。
- **L7 哈希算法**：仅 SHA-1 仓库。
- **L8 二进制差异**：只报 differ，不出内容级 diff（§11.2）。
- **L9 无提示交互**：不交付「运行时弹窗索要凭据」，缺凭据只给指引。
