## 1. 目的

Pi Web 的「选择工作区目录」对话框目前只有**单列列表 + 自由文本路径输入**，起点落在应用沙箱内：

- 沙箱 `HOME` 被壳重定向到 `userData`（`src-main/main.js#assembleSandboxEnv`），于是 `getBrowseStartDirectory()` 返回 `homedir()` = `<userData>` —— 一个混杂 `Cache/`、`pi-agent/`、`pi-dist/` 的内部目录；
- 已授权的用户目录（桌面 / 文档 / 下载，`/storage/Users/currentUser/{Desktop,Documents,Download}` ✅ 真机实测存在）需要用户**自己知道并手输绝对路径**才能用上；
- 对话框可一路 `parentPath` 点到 `/`，也可提交任意绝对路径，没有浏览域边界。

本设计交付**四主目录选择器**：对话框顶部可切换 **沙箱 / 桌面 / 文档 / 下载**，切换后在对应目录**内部**完成列目录、下钻、新建文件夹、选择；浏览域锁定在该主目录内（只向下、不上溯、无手输路径）。

|---|---|---|
| F1 | Next 服务器与 Electron 主进程**同进程** | 壳侧用**环境变量**即可把数据交给 pi-web 的 HTTP 路由；不需要 IPC、不需要自定义协议（`docs/工程规划.md` §4.2） |

| F4 | `electron.systemPreferences.checkPermission(permissions: string[])` → **同步** `boolean[]` | ✅ 实测可调（`[false,false,false]`）。⚠️ **但它有假阴性**：用 `atm perm -g` 授予权限后四根**实际可读写**，`checkPermission` 仍返回 `false`（重启后依旧，`logs/20261014-2/T24`/`T39`）。因此它**只能作失败时的归因线索（区分话术），绝不作「是否可用」的门禁** |

## 4. 用户故事

- 作为用户，我希望在「选择工作区目录」里直接切到桌面/文档/下载，把这些已授权目录中的文件夹注册为工作区。
- 作为用户，我希望选定主目录后能进入子文件夹、新建文件夹并选中，以精确指定工作区位置。
- 作为用户，我希望沙箱里有一个稳定的默认工作区根，不必手工创建。
- 作为用户，当我切到某个用户目录读不了时，我希望看到**为什么**读不了，并有一键去系统设置的入口。
- 作为用户，我希望下次打开对话框时默认停留在上次使用的主目录。
- 作为排障者，我希望 `--inspect` 与 `/roots` 能直接给出四个主目录的解析结果与授权状态。


组件边界（单一目的、可独立理解）：

| 单元 | 输入 | 职责 | 依赖 | 回引 |
|---|---|---|---|---|
| `RootTabs` | `roots[]`、`activeRootId` | 渲染四 Tab，切换时上抛 rootId | 无 | FR-203-005 |
| `useRoots()` | — | 从 browse 响应取 `roots`，缺省 `sandbox` | `/api/cwd/browse` | FR-203-004 |
| `BrowseStack` | `rootId`、`rootPath` | 维护 `currentPath`/`entries`/`truncated`/`loading`/`error`；下钻只接受条目路径 | `/api/cwd/browse` | FR-203-006/009 |
| `Breadcrumbs` | `rootPath`、`currentPath` | 相对主目录根生成、最高到根 | 无 | FR-203-008 |
| `NewFolderModal` | `currentPath`、`entries` | 默认名 + 同级去重 → `POST` → 刷新并选中 | `/api/cwd/browse` | FR-203-011…013 |
| `PermissionNotice` | `error.code`、`root.permType` | 归因 +「去系统设置」+ 重试 | `__PI_HOS_PERMISSION__` | FR-203-015/016 |
| 主目录记忆 | — | `localStorage` 只存 rootId，非法回退 `sandbox` | 无 | FR-203-018 |

数据通道纪律：组件**不读** `electron`、**不读**环境变量；一切数据来自 HTTP 路由或 `__PI_HOS_PERMISSION__`。

## 8. 根围栏（安全属性）

浏览域被锁定在选定主目录内，**这是安全属性，不是待修的缺陷**：

1. 列目录第一列锁定为该主目录根的 `list` 结果；下钻只接受当前列条目产生的子路径（FR-203-009）。
2. 面包屑点击目标最高为主目录根，根之上层级不渲染（FR-203-008）。
3. 无手动路径输入，UI 层不存在提交任意绝对路径的入口（FR-203-007）。
4. 主目录切换必须经 `RootTabs` 重置整栈（FR-203-005）。

因此四个主目录互为隔离浏览域：可向下自由穿越，不能上溯，不能横向越界。

## 9. 数据流

```
启动期（主进程）
  assembleSandboxEnv()          HOME/USERPROFILE → userData
  installWorkspaceRoots()       四根解析 + 沙箱根 mkdir + PI_HOS_ROOTS
  installPermissionBridge()     __PI_HOS_PERMISSION__ 就位
  进程内 Next 服务器就绪         → 补丁后的 /api/cwd/browse 可读 PI_HOS_ROOTS
  client-modules 扫描           → extensions/harmony-workspace-roots.js 装载

交互期（渲染进程）
  打开「选择工作区目录」
    rootId ← localStorage（非法 → sandbox）
    GET /api/cwd/browse?root=<id>
      → resolveWorkspaceRoot(id) 取主进程已解析的根
      → listDirectories 过滤 hidden 与非目录 + truncated
    → RootTabs + Breadcrumbs + 列表
    下钻：GET /api/cwd/browse?path=<条目 path>
    EACCES/EPERM → __PI_HOS_PERMISSION__.check(permType)
      ├ true     → 视为瞬时错误，直接重试
      ├ false    → PermissionNotice：归因 +「去系统设置」(openAppInfo) + 重试
      └ available=false → 明确归因，不静默
    新建：POST /api/cwd/browse {path,name} → 刷新 → 选中
    选择：onSelect(绝对路径) → 上游 /api/cwd/validate → createWorkspace → allowFileRoot
```

## 10. 授权流程

```
list 返回 EACCES/EPERM
         │
         ▼
主进程桥 check(permType)
   └ checkPermission(['ohos.permission.READ_WRITE_{DESKTOP,DOCUMENTS,DOWNLOAD}_DIRECTORY'])
         │  （同步 boolean[]，✅ 实测）
    true ├─► 视为瞬时错误，重试 list
         │
   false ▼
   PermissionNotice（对话框内，不关闭）
     ├ 归因说明：该目录需要在系统设置中授权
     ├ 「去系统设置」→ openAppInfo()  （✅ 实测：openApplicationInfoEntry，无参同步）
     └ 返回后「重试」手动重列
```

`permType` 映射（`web_engine/src/main/ets/adapter/PermissionManagerAdapter.ets` 的 `needPermissions` 表）：
`directory_desktop → READ_WRITE_DESKTOP_DIRECTORY`、`directory_document → READ_WRITE_DOCUMENTS_DIRECTORY`、`directory_download → READ_WRITE_DOWNLOAD_DIRECTORY`。

**F4 的使用纪律（务必遵守）**：`checkPermission` 的 `false` **不是**「不可用」的证据（见 F4 的假阴性）。对话框只在**列目录已经失败**之后才去问它，且只用来在三种话术间选择：① 已授权 → 「暂时无法读取 + 重试」；② 未授权且该根有 `permType` → 「去系统设置」；③ 其它（含沙箱）→ 通用「无法读取 + 重试」。**任何**情况下都不因为它返回 `false` 就阻止重试，也不据此隐藏入口。`

**未采用的通路**：`requestDirectoryPermission`（参数形状已探明但主进程调用不 settle，F6）与 `callArkTSFunction` 权限桥（会打崩进程，F7）。两者的定论方式已登记 `specs/203-plugin-workspace-picker/spec.md` FR-203-017。

## 11. 错误处理

| 场景 | 表现 |
|---|---|
| 主目录不可读（未授权） | 走 §10；不把原始 `EPERM` 抛给用户，不静默 |
| 主目录解析失败（`PI_HOS_ROOTS` 缺项） | 该 Tab 可见但内容区显示不可用说明 + 重试；**不回退其它主目录** |
| 沙箱根创建失败 | 内容区显示失败原因 + 重试 |
| 新建目录同名 | Modal 内提示冲突，保留输入态 |
| 新建目录失败 | Modal 内提示，可改名重试 |
| `entries` 触顶（后端上限 1000） | 展示 `truncated` 文案 |
| 采纳工作区失败 | 复用既有错误 Modal（含重试） |
| 权限桥不可用 | 明确归因（`available:false`），不假装成功 |

浏览类失败在对话框自有区域内消化；只有采纳阶段错误进入上游错误链路。

## 15. 约束与已知限制

- 只面向**四个主目录**；不提供整盘浏览，不恢复手动路径输入（FR-203-007）。
- **不重造 Miller 多列视图**（FR-203-010 有意偏离）：保留 pi-web 原生单列列表面板，避免把补丁面从「加一行 Tab」扩大到整套布局代码。
- **对话框内主动申请授权未通过 PoC**（FR-203-017）：`requestDirectoryPermission` 的主进程调用不 settle。v1 走「预检 + 去系统设置」；用户需在系统设置授权并**重启应用**后写入才生效（与 `skills/harmony-runtime-capabilities` 的既有结论一致）。
- 桌面目录为 `system_basic`（需 ACL），上架前必须按 `docs/ACL申请清单.md` 复核；失败不影响沙箱/文档/下载。
- `entries` 上限 1000 为后端既有行为，超限只提示不分页。
- 仅支持选择目录，不支持文件选择、多选。
