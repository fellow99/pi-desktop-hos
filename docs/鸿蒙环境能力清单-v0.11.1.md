### C.3 逐项根因结论（只列有实质判定的项）

1. **#3 SWC**：上游无 `@next/swc-linux-arm64-ohos`。解法 = **内置平台无关的 WASM 版 SWC**，放**唯一生效落点**
   `node_modules/next/wasm/@next/swc-wasm-nodejs/`（`scripts/collect-pi.mjs` 的 `provisionWasmSwc()`）。
   真机证据：`Running next.config.ts took 228–236 ms` + `files/tmp/next-swc` 缓存目录**从未创建**（零下载尝试）。
   → **L2 已解**。
2. **#11 符号链接**：应用域与 shell 域**都** `EACCES`/`Permission denied`。pi/pi-web 的写路径**不使用 symlink**
   （`patches/README.md` 候选 7：创建型调用 0 处），故**无实际影响**。→ **L1，不需处置**。
3. **#12 `chmod`（安全前提已核实）**：`pi-web/lib/provider-credential-store.ts` 依赖
   `chmodSync(authPath, 0o600)` 保护凭据。应用域实测沙箱 `hmfs` 如实生效；真机回读
   **`pi-agent/auth.json` → `mode=0600`、`size=95`、providerKeys `["deepseek"]`、`type=api_key`**
   （密钥脱敏为 `sk-e32……a17f（len=35）`）。→ **该安全假设在设备上成立**（这是「用户目录 `hmdfs`
   静默改写」**不适用**于本工程的关键理由）。证据：`T08-credential-and-spawn.txt`。
4. **#15 子进程结束事件**：单次 `spawn` 探针（复刻 pi `bash` 形状，`detached: true` + `stdio` 双管道）：
   `spawn@56ms` → `stdout@69ms` → `stdout@97ms` → **至 6061 ms 再无任何事件**；`exitCode`/`signalCode` 恒 `null`；
   `/proc/<pid>/stat` 状态在 1557 / 3058 / 4560 / 6061 ms 四次采样**全为 `Z`**。
   → **L1**。pi 的 `bash` 工具用 `waitForChildProcess(child)` 等 `exit`/`close` 判定结束
   （`utils/child-process.ts` 的三条决胜路径**全部以事件为前置**：`close` / `exit` + stdout·stderr 双 `end` /
   `exit` 后 100 ms 空闲；**无轮询、无绝对截止时间**），而 `bash.ts` 的 `timeout` 判定在 `await` **之后**
   → **等待无上界**。**本工程的用户可见缺口**，非上架阻塞。
5. **#16 PTY**：应用域 `/dev/ptmx` 可 `open`；`node-pty` 在 `require` 期即因缺
   `prebuilds/openharmony-arm64/pty.node` 失败。→ **阻断点已证为 L2**（交叉编译可解，优先级高于参考工程的同项）。
   ⚠️ **L1 未证伪**：`grantpt`/`forkpty` 从未被尝试，不能据此断言「内核不拒绝 PTY」。
6. **#17 子进程 Node**：`node -v` 有输出而 `node -e` 无输出 → 失败发生在**真正执行代码**之后。
   ⚠️ **终止原因未取得**（`exit` 不来、`signalCode` 恒 `null`），故**不能断言**是 SIGSYS/seccomp 拒绝 JIT；
   与「seccomp 拦 JIT」的解释**相容但不构成证明**。→ **L1 + 未归因**（诚实标注）。
   注：随包交付的 `skills/harmony-runtime-capabilities/SKILL.md` 与 `extensions/harmony-runtime.js` 曾把
   `Signal 31 (core dumped)` 写成**既成事实**；本轮已按证据把这两处改为「参考工程记录如此，本工程复测未取得终止原因」。
7. **#23 toybox**：用**修正后的判据**枚举（见下），结果与参考文档**同构同数**：编译 **178** / 177 / 1 / 42 / 11 遮蔽 / 139 恒等 alias。
   两处**方法学修正**（本轮实测得出，且是「怎么判」而不是「判出什么」）：
   - **不能用 `toybox <n> --help` 判「可派发」**：`grep`/`diff`/`env`/`sort`/`cmp`/`chroot`/`timeout`/`false`
     等小程序**不接受** `--help`（返回非零），会被误判为不可派发。**正确判据** = 「该名是否在
     裸 `toybox` 输出的小程序表内」。用错判据时 11 个小程序被误判，A 类从 177 掉到 166。
   - **不能用 `[ -L ]` 判是否软链**：shell 域对**单条目**的 `lstat` 被拒（`ls -l /system/bin/cat` → `Permission denied`），
     `[ -L ]` **恒假**，会把 230 个软链**全部**误判为普通文件。**正确做法** = `ls -l /system/bin`
     **目录列表**（可读）+ `readlink`（可读）。
   - ⚠️ 两个错误**是同时发生的**，因此 v1 一次性产出的错误形态是：所有条目都被归到「非软链」，
     其中 11 个小程序被判成不可派发，而「悬空软链」计数变成 **0**（不是「小程序被误判成悬空软链」）。
     A 类最终数字从 166 纠正为 177。
8. **#14 用户目录**：四个目录存在（`02771` / `uid=20001006` / `gid=1006`）但应用写入 `EPERM`，
   **提权审批也不改变这一点**（属 OS 授权门而非应用内围栏）。→ **L1**，只能靠系统设置授权 + 重启。
9. **#29 后台常驻**：Home 键后窗口 `WINDOW_OCCLUDED(5)`、运行时下调进程优先级
   （`SetProcessPriority … priority: 1`），但 Ability **状态不动**（仍 `FOREGROUND`）、`isKeepAlive: false`、
   无 `onBackground`。→ **L3**，需声明常驻 + 无窗形态才能真实驻留。

### C.4 安全与「陷阱」清单（本轮实测复现的）

1. **`reboot` → `begetctl` 的回弹陷阱（跨设备复现）**：`/system/bin/reboot` 是指向 `begetctl` 的软链。
   以**裸名**跑 `--help` 之类参数会被 `begetctl` 当命令执行 —— **本轮把设备重启了**（`uptime` 归零至 `up 0 min`）。
   安全做法：**只对 `toybox <n>` 传参**，且**先确认 `<n>` 在裸 `toybox` 的小程序表内**；`reboot` **不在**表内
   （→ `Unknown command`，安全）。**任何批量探测 `/system/bin` 的脚本都必须先过这一条。**
2. **`command -v` 不可作为「可执行/在哪」的判据**：139 条恒等 alias（`alias cat=cat`）会让
   `command -v cat` 返回 `alias cat=cat`；而 `which cat`（toybox 小程序）返回 `/bin/cat` ——
   **两个答案不同，不可混用**。要真判名字归属，须 `unalias` 后 `type`。
3. **跨域可见性（含 ENOENT 伪装）**：同一路径在两个 SELinux 域下结论不同，且**不可见时可能报 `ENOENT` 而非 `EACCES`**：
   `ls -ld /data/service/hnp`（shell 域）→ `No such file or directory`，而应用域 `statSync` → 存在 116,927,320 B；
   `/data/storage/el2/base/files`（shell 域）→ `Permission denied`。→ 结论必须标明**取证域**
   （本文 §D.1 每条都标）。**不要**用 shell 域的 `ls/stat` 去判 HNP / 系统挂载点是否存在。
4. **`snapshot_display` 不能判白屏**：能出图（3120×2080）但 Electron 的 GPU 合成面拍不到
   （轮次 1 实测 99.3 % 纯白）。判据应用 **DOM 探针**或 **`webContents.capturePage()`**。
   本轮补充：**`uitest dumpLayout` 能直接取到 UI 文本**（本轮用它取到锁屏文案「请输入密码」）
   → 比截图更可靠且更省事。
5. **`hdc fport` 的生命周期与残留**：映射随发起它的 `hdc` 客户端**退出即失效**（`fport ls` 变 `[Empty]`）；
   而**残留映射会让新映射建立失败**（`TCP Port listen failed at <port>`），同一 inspector 上会累积多条转发。
   → 「建转发 + 消费」必须在**同一条命令内**完成，并在建立前 `hdc fport rm tcp:<port>`。
6. **`hdc` 的参数会被 Git-Bash 改写**：设备路径可能被 MSYS 转换；`hdc file send <本地绝对路径>`
   会被拼成 `<cwd>/C:/...` 而报 no such file。可靠做法：① 设备侧路径前加 `MSYS_NO_PATHCONV=1`；
   ② 传文件改用 **base64 经 `hdc shell` 落地**（本轮即用此法，`md5sum` 校验一致）。
7. **`hdc` 偶发 `need connect-key` / `channel being established`**：几乎每次操作都可能命中，
   **所有 hdc 调用都必须带重试**（本轮统一用带重试的封装）。
8. **锁屏会阻断部署**：设备重启后若锁屏，`aa start` 直接失败
   （`10106102 The device screen is locked during the application launch, unlock screen failed`）；
   开发者模式下无法自动解锁，`power-shell wakeup` 在 shell 域被拒，`uitest uiInput`
   也无法越过**密码**锁。→ **部署前先确认屏幕已解锁**。
9. **一次未定的应用进程替换**：本轮开发过程中一次多进程探针运行后，应用进程被替换
   （`25334` → `26601`，15:55 前后）。**未能定位触发点**：无 faultlog、无 OOM/被杀记录；hilog 中同期只有
   `F LIBUV: errno:13, sig_lock_pfd`（该行在**正常运行**时也周期性出现，属噪声），
   以及用户点击更新提示后的 `GetJSFunction ExternalWeb.Open failed`。
   **单次与连续两次 `spawn` 复测均不触发**。→ 诚实标注为**未定**，列入 §B #2。

### C.5 `fork`/`exec` 与由此导出的设计约束

| 观测 | 结果（证据：`T08-credential-and-spawn.txt`） |
|---|---|
| `spawn('/system/bin/sh', ['-c','echo spawn-ok; id'])` | ✅ 命令执行；事件 `spawn@56ms` / `stdout@69ms` / `stdout@97ms` |
| 子进程身份 | `uid=20020215(pci) gid=20020215(pci_a20215) groups=… context=u:r:debug_hap:s0`（**应用身份**，非 shell 身份） |
| `exit` / `close` / `error` 事件 | ❌ 至 **6061 ms** 为止**全部缺席**；`exitCode` / `signalCode` 恒 `null` |
| 子进程终态 | 1557 / 3058 / 4560 / 6061 ms 四次采样**全为 `Z`**（僵尸），长期不回收 |
| `spawn('/data/service/hnp/bin/node', …)` | `-v` → `v24.13.0`（能跑）；`-e 'console.log(1+1)'` → **无输出** + `Z`（证据：`T10-node-subprocess.txt`） |

**由此导出两条不可违反的设计约束**：

1. **宿主自身绝不 spawn**（本工程已遵守：Next 服务器进程内嵌，宿主零子进程）。这是规避
   「`exit` 不可观测 + 每 spawn 泄漏僵尸 + 子进程 JIT 被拦」的唯一低成本方式。
2. **面向用户的 `bash` 工具必须换实现或加兜底**（当前不满足）：pi 的 `waitForChildProcess()`
   无轮询、无截止时间；`bash.ts` 的 `timeout` 判定在 await 之后 → 一次 `bash` 调用会挂住整个会话。见 §B #1。

**本版本补丁集为 0 条**（`patches/` 下无补丁文件，`patches/v0.11.1/` 目录不建）。
**8 个候选**（7 条原有 + 1 条本轮新增）逐条源码核实见 `patches/README.md` §v0.11.1 基线复核；

→ **上游升级时只需逐条复核那 8 条候选的文件路径，不需要重跑构建来「试出」补丁。**

### C.7 文件围栏（与参考工程的关键分歧）

pi 的文件审批流是**工具层**的（`read`/`write`/`edit` 走围栏）。但 **`bash` 子进程以应用 uid 运行**，
按定义**绕过**该围栏 —— 与参考工程结论一致。本工程的处置是**技能层显式告知**
（`skills/harmony-runtime-capabilities/SKILL.md` 写明「`bash` 无围栏、优先用 read/write/edit」），
**属于最佳努力，不是沙箱**。若要真围栏，需要壳扩展在 exec 层做路径白名单。→ **L4，未处置。**

### C.8 二进制证书 / 自有 ELF

本工程**不随包分发自有 ELF**（运行时 `.so` 来自上游 Electron-on-鸿蒙运行时归档，属「消费上游产物」）、
不使用 HNP，因此**不需要**二进制证书（AGC `certType: 4`）与 `ALLOW_EXTERNAL_NATIVE_CODE`。→ **N/A**。
上架只需 ACL 受限权限 `ohos.permission.kernel.ALLOW_WRITABLE_CODE_MEMORY` —— 本轮用
`hap-sign-tool verify-app` 独立复验了签名与 Profile：`Digest verify result: true` / `verify-app success`，
`Signature Algorithm: SHA384withECDSA`，`bundle-name = org.fellow99.pi.PiDesktop`、`type = debug`，
且 `acls` 内含 `kernel.ALLOW_WRITABLE_CODE_MEMORY`。详见 `docs/工程规划.md` §11.4/§11.5。

### D.2 平台事实（本轮核实）

1. 应用进程 uid/gid `20020215`，SELinux 域 `u:r:debug_hap:s0`（**debug** 构建；release 签名包不可侧载）。
2. 应用进程拓扑：主进程 + `:NetworkService` + `:GPU` + `:Renderer`（Chromium 多进程），全部同一 uid。
3. 应用沙箱根 `/data/storage/el2/base/files` 为 **`hmfs`**；用户目录卷为 **`hmdfs`**；
   两者的 `chmod` / 硬链接 / symlink 语义**不同**（见 §C.2）。
4. **shell 域对同一路径可能报 `ENOENT` 而非 `EACCES`**：`ls -ld /data/service/hnp` → `No such file or directory`，
   而应用域 `statSync` 存在。→ 「shell 域看不到」**不等于**「不存在」；反之 shell 域的 PATH 级
   `command -v node` = absent **只**能证明不在 PATH，**不能**证明不可见（本文已据实测数据区分这两件事）。
5. shell 域 `ln -s` 与 `ln`（硬链接）**都被拒**（`Permission denied`）；`chmod 640` 在 shell 域如实生效。
6. shell 域对 `/system/bin` **单条目** `lstat` 被拒（`ls -l /system/bin/cat` → `Permission denied`、`[ -L ]` 恒假），
   但**目录列表可读**、`readlink` 可读 → 枚举须走目录列表（§C.3 #7）。
7. `uname -a` 尾部 `Toybox` 是**内核 utsname 字段**，不是 shell 身份；`/proc/self/exe` 之类探针同样不可信。
   权威判据是 `KSH_VERSION`。
8. 服务端监听 `0.0.0.0:<随机端口>`，渲染层经**局域网 IP** 访问（`PI_WEB_HOSTNAME=192.168.137.31`）；
   Host 围栏对 IP 字面量放行，**无需头改写**。
9. `PI_WEB_PASSWORD` 每启随机（43 字符，**从不回显**）；Basic 用户名固定 `pi`（`pi-web/lib/web-auth.ts`）。
10. `PI_OFFLINE=1` 默认开启 → pi 永不尝试下载外部二进制/包（#18/#19/#20 的直接原因）。
11. 设备重启后应用**不自启**；且**锁屏会阻断 `aa start`**（密码锁下无法自动解锁）。
12. `/data/local/tmp` 在设备重启后**仍持久**。
13. `uitest uiInput`（`keyEvent` / `swipe` / `text` / `dumpLayout` / `screenCap`）在 shell 域可用 →
   是**交互注入与 UI 文本取证**的可用通道；`text` 只能在已聚焦处输入，**无法输入密码锁屏**。
14. `snapshot_display` 可出图但拍不到 GPU 合成面；`uitest dumpLayout` 直接给 UI 文本，是更优判据。
15. Node 运行时 `22.17.0`（Electron 37 内置）；**CDP 默认执行上下文没有 `require`/`module`/`exports`**，
   可用入口是 `process.getBuiltinModule('node:fs')` 或 `process.mainModule.require('electron')`。
16. HAP `pack.info` 报 `apiVersion compatible 17 / target 24`，而设备系统 API 为 **26** —— 二者不矛盾
   （前者是应用声明，后者是设备能力）。
17. 硬件 I²C / 内核模块类 toybox 小程序（`insmod`/`lsmod`/`iptables*` 等）属系统级，本轮**未使用**。

### REV-1.2 实现机制（两条扩展，均为自包含单文件）

| 扩展 | 顶替的工具 | 机制要点 |
|---|---|---|
| `extensions/harmony-exec.js` | `bash` | 常驻 `/system/bin/sh`（**惰性启动**，`session_shutdown` 幂等释放）+ 帧协议：`__PI_BEGIN__ <tok>` … `( cd <cwd> \|\| { echo 'cd failed: …' >&2; exit 1; }; <command> ) </dev/null 2>&1; __PI_END__ <tok> <rc>`。**子 shell 括号组**（非花括号组）→ 命令里的顶层 `exit` 只结束子 shell，**不杀常驻 shell**（真机 `exit 3` → rc=3 且 shell 存活）；stderr 合并；命令 stdin 为 **`/dev/null`**（与内建 `stdio: ignore` 同语义，且使读 stdin 的命令不会吃掉帧尾）；**默认 120 s 超时** + 2 s 排干 + 重置（**超时仍返回已产出的输出**）；重置杀**整个进程组**（`detached: true` + `kill(-pid)`，被中断命令的子进程不会污染后续结果）；输出 256 KiB 截断并显式标注（按 UTF-8 字节、不切多字节字符）；串行队列（并发调用不交错写同一 stdin）；每个 shell 一份状态对象（旧 shell 的迟到 `end` 不会误杀新 shell）。**工厂内零长驻资源**（遵守 pi 扩展契约） |

### REV-1.3 新的信任模型与限制（**必须知道**）

1. **信任模型未改变**（重申 §A #32 / spec C1）：顶替后的 `bash` **仍然没有**路径围栏 —— 命令以应用 uid 运行，
   可读写应用能到达的任何位置，**绕过 pi 的文件审批流**。缓解手段**仍只是技能层约束**（`skills/harmony-runtime-capabilities/`）。
   **「修好了 `bash`」不等于「有了沙箱」。** 命令围栏在本轮**有意不做**（会让含 `$VAR`/管道/`xargs` 的合法命令 fail-closed），登记为可选后续。
2. **仍然没有 PTY**（#16 不变）：常驻 shell 是**非 PTY** 管道；交互式全屏程序（`top`/`vi`）不可用。
3. **`cd` 与 shell 变量不跨命令保留**：每条命令都在**子 shell** 里以 `cd <会话工作目录>` 开头（与内建「每条命令新建 shell」同语义）；工作目录不存在时**立刻失败并报 `cd failed: …`**。
4. **shell 状态不跨重启保留**：命令里顶层 `exit`/`exec`、超时、外部 `SIGKILL` 都会重置常驻 shell，下一条命令自动重启（**状态清空**）。
5. **僵尸净减少**：常驻复用（真机 9 条命令只 `spawn` **1 次**）远少于内建「每条命令 1 个僵尸」；但**并没有消除**子进程 `exit`/`close` 缺失这一平台事实（#15 的 L1 根因仍在，只是被绕开）。
6. **命令的 stdin 是 `/dev/null`**：与内建一致（内建用 `stdio: ["ignore", …]`）。因此 `cat` / `read` / 不带文件参数的 `grep` **立即返回空输入**，不会挂住；反过来说，本工具**不能给命令喂 stdin**（需要输入的命令请改用参数/重定向）。
7. **搜索的忽略规则是近似**：**不解析 `.gitignore`**，只跳过点目录 + `node_modules` + `.git`；而内建 `grep`/`find` 会传 `--hidden`（**默认包含隐藏项**）→ 本实现对隐藏项**更保守**。单文件 >512 KiB **跳过并计数**。
8. **输出路径基准是会话 cwd**：因此打印出的路径可直接喂给 `read`/`write`/`bash`；内建 `grep` 在 `path` 为目录时改用「相对搜索路径」、`find` 用「相对搜索根」，属**有意保留的差异**（对读者更可用）。
9. **不注入会话环境变量**：内建 `bash` 会注入 `PI_SESSION_ID`/`PI_SESSION_FILE`/`PI_PROVIDER`/`PI_MODEL`，本扩展**不注入**（常驻 shell 继承应用进程的环境）。
10. **仍未在真机构造验证的边界**（诚实标注）：256 KiB 输出截断路径、`MAX_FILES 2000` / `MAX_DEPTH 8` 触顶、外部 `SIGKILL` 致死路径。其余上限（结果数 `limit` 的目录/单文件两种情形、单行截断、超大文件跳过、非法 glob/正则、路径不存在）**已在宿主侧单测 `scripts/test-harmony-tools.mjs`（33 条断言）覆盖**。
