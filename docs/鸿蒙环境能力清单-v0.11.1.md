## C. 关键结论与依据

### C.1 根因分层模型（L1–L4）

| 层 | 性质 | 可恢复性 | 本工程涉及项 |
|---|---|---|---|
| **L1** 平台硬约束 | SELinux / seccomp / 内核 ABI / OS 授权门 | **不可恢复**（只能绕） | #11 符号链接、#14 用户目录写、#15 子进程结束事件、#17 子进程 Node、#31 开机自启 |
| **L2** 原生产物缺失 | 缺某架构的 `.node` / 外部二进制 | **可恢复**（交叉编译或内置替代） | #3 SWC（已解）、#16 PTY、#18 `fd`、#19 `rg` |
| **L3** 本工程配置 | 我们自己的策略选择 | 可改（改本工程） | #20 仅本地源、#29 后台常驻声明 |
| **L4** 上游接口缺失 | pi / pi-web 没有该能力或该工具 | 需上游改动或壳扩展 | #32 文件围栏（`bash` 不可围）、`bash` 工具的超时语义 |

### C.2 与参考工程的对照（同型但**不同结论**的地方）

同一类设备、同一运行时家族，但本工程与 `dsh-desktop-hos` **能力面差异是结构性的**，逐条比对得出：

| 维度 | dsh-desktop-hos（参考） | pi-desktop-hos（本工程） | 差异原因 |
|---|---|---|---|
| 服务端形态 | 壳内起服务 + 插件层 | **主进程进程内嵌 Next 服务器，零子进程** | 规避「子进程 exit 不可观测 + 每 spawn 泄漏僵尸 + 应用域 JIT 被拦」三个平台问题（本报告 #15/#17 正是这三条的证据） |
| Host / Origin 头改写 | 需要一整套补丁 | **完全不需要** | pi-web 的 `lib/request-security.ts:97` 对 IP 字面量直接放行；同源请求天然通过（`patches/README.md` 候选 6） |
| 上游补丁集 | 14 条（补丁链） | **0 条** | `pi`/`pi-web` 的现成机制覆盖了全部候选（Node 门禁不触发、`PI_OFFLINE` 首行短路、无 `node:sqlite` 路径、zstd 有运行时守卫、无硬原生依赖、Host 围栏天然放行、写路径不用 symlink） |
| `chmod` 语义 | 用户目录 `hmdfs` 静默改写（640→660） | **沙箱 `hmfs` 如实生效**（600/640/755 全部回读正确） | 本工程所有写路径都在沙箱内 |
| 硬链接 | 用户目录 `hmdfs` 拒绝 | **沙箱 `hmfs` 成功** | 同上 |
| 符号链接 | 应用域 `EACCES`、**shell 域允许** | **两域都拒绝** | 本机 OS 版本更新（参考设备 API 24 / 本机 **API 26**），shell 域策略收紧 |
| PTY 根因 | **L1** SELinux 拒 `forkpty`/`openpty` | **L2** 缺 `openharmony-arm64` 原生产物（`/dev/ptmx` 可打开） | 本机没有内核层面的 PTY 拒绝迹象；阻断点前移到缺产物 → **可修**（优先级比参考工程高） |
| `/data/service/hnp/bin/node` | 应用域可见、shell 域不可见（记为陷阱） | **同样复现**（应用域存在 111.5 MB，shell 域 absent） | 一致 |
| `node -e` 无输出 | 3 次复现，原因未定 | **第 4 次复现**（同样无 stdout/stderr + 僵尸） | 一致 |
| 探测脚本危险模式 | 文档记载「裸名 `--help` 探测 `reboot` 会重启设备」 | **本机 100% 复现**（本轮实测把设备重启了，见 §C.4） | 同一陷阱，跨设备成立 |

### C.3 逐项根因结论（只列有实质判定的项）

1. **#3 SWC**：上游无 `@next/swc-linux-arm64-ohos`。解法是**内置平台无关的 WASM 版 SWC**并放对**唯一生效落点** `node_modules/next/wasm/@next/swc-wasm-nodejs/`（`collect-pi.mjs` 的 `provisionWasmSwc()`）。真机证据：`Running next.config.ts took 228 ms` + `tmp/next-swc` 缓存目录**从未创建**（零下载尝试）。→ **L2 已解**。
2. **#11 符号链接**：应用域与 shell 域**都** `EACCES`。pi/pi-web 的写路径**不使用 symlink**（`patches/README.md` 候选 7 源码核实：创建型调用 0 处），故无实际影响。→ **L1，不需处置**。
3. **#13 `chmod`**：`provider-credential-store.ts` 依赖 `chmodSync(path, 0o600)` 保护 `auth.json`。实测沙箱 `hmfs` 如实生效 → **该安全假设在设备上成立**。真机核对：`pi-agent/auth.json` 的 `mode=0600`。→ **✅ 假设成立**（这是「用户目录 `hmdfs` 静默改写」不适用于本工程的关键理由）。
4. **#15 子进程结束事件**：逐层探针（单次 `spawn`）显示 `spawn` 事件到达、stdout 完整、6 s 内 `exit`/`close`/`error` **全部缺席**、`/proc/<pid>/stat` 状态为 `Z`。→ **L1**；pi 的 `bash` 工具用 `waitForChildProcess(child)` 等 `exit`/`close` 判定结束（`utils/child-process.ts` 三条决胜路径**全部以事件为前置**，无轮询、无绝对截止），`bash.ts` 的 `timeout` 判定在 await **之后** → **等待无上界**。**本工程的用户可见缺口**，非上架阻塞。
5. **#16 PTY**：本工程**有** `/dev/ptmx` 可打开，但 `node-pty` 无 `openharmony-arm64` 预编译产物 → `require` 失败即降级（`lib/terminal-manager.ts` 的 try/catch）。→ **L2**，可用交叉编译消除（**优先级高于参考工程的同项**，因为它不是内核拒绝）。
6. **#17 子进程 Node**：`node -v` 有输出而 `node -e` 无输出 → 失败发生在**真正执行代码**之后，与「seccomp 拒绝 JIT 的可执行内存」的解释一致；但**本轮无法取得终止原因**（`exit` 事件不来，`signalCode` 恒 `null`）。→ **L1，且本轮无法进一步归因**（诚实标注）。
7. **#23 toybox**：枚举结果与参考工程**同构且同数**（178 / 177 / 1 / 42 / 11 遮蔽）。补充两处**方法学修正**（本轮实测得出）：
   - **不能用 `toybox <n> --help` 判「可派发」**：`grep`/`diff`/`env`/`sort`/`cmp`/`chroot`/`timeout`/`false` 等小程序不接受 `--help`，会被误判成「悬空」。判据应改用**「该名是否在裸 `toybox` 输出的小程序表内」**（本报告即用此判据，A 类从 166 纠正为 177）。
   - **不能用 `[ -L ]` 判是否软链**：shell 域对**单条目**的 `lstat` 被拒（`ls -l /system/bin/cat` → `Permission denied`），`[ -L ]` **恒假**，会把 230 个软链全判成普通文件。可靠做法是 `ls -l /system/bin` **目录列表**（可读）+ `readlink`（可读）。
8. **#14 用户目录**：目录存在（`02771`, `uid=file_manager`）但应用写入 `EPERM`，**提权审批也不改变这一点**（属 OS 授权门而非应用内围栏）。→ **L1**，只能靠系统设置授权 + 重启。
9. **#29 后台常驻**：Home 键后窗口 `WINDOW_OCCLUDED(5)`、运行时下调进程优先级（`SetProcessPriority … priority: 1`），但 Ability **状态不动**（仍 `FOREGROUND`）、`isKeepAlive: false`、无 `onBackground`。→ **L3**，需声明常驻 + 无窗形态才能真实驻留。

### C.4 安全与「陷阱」清单（本轮实测复现的）

1. **`reboot` → `begetctl` 的回弹陷阱（跨设备复现）**：`/system/bin/reboot` 是指向 `begetctl` 的软链。以**裸名**跑 `--help` 之类的参数会被 `begetctl` 当命令执行 —— **本轮把设备重启了**（`uptime` 归零）。安全做法：**只对 `toybox <n>` 传参**，且**先确认 `<n>` 在裸 `toybox` 的小程序表内**；`reboot` **不在**表内（→ `Unknown command`，安全）。**任何批量探测 `/system/bin` 的脚本都必须先过这一条。**
2. **`command -v` 不可作为「可执行/在哪」的判据**：139 条恒等 alias（`alias cat=cat`）会让 `command -v cat` 返回 `alias cat=cat`；而 `which cat`（toybox 小程序）返回 `/bin/cat` —— **两个答案不同，不可混用**。要真判名字归属，须 `unalias` 后 `type`。
3. **跨域可见性**：`/data/service/hnp`、应用沙箱（`/data/storage/el2/base/files`）在 **shell 域不可见**（`Permission denied`），只有**应用域**能观测。任何关于这两处的结论**必须从应用域取证**（本报告的 #25 与 #3 落点证据都走 CDP 应用域）。
4. **`snapshot_display` 不能判白屏**：能出图（3120×2080）但 Electron 的 GPU 合成面拍不到（轮次 1 实测 99.3 % 纯白）。判据应用 **DOM 探针**或 **`webContents.capturePage()`**。本轮补充：**`uitest dumpLayout` 能直接取到 UI 文本**（本轮用它取到锁屏文案「请输入密码」）→ 比截图更可靠且更省事。
5. **`hdc fport` 的生命周期**：映射随发起它的 `hdc` 客户端**退出即失效**，``fport ls`` 变 `[Empty]`；且**残留映射会让新映射建立失败**（`TCP Port listen failed`）。「建转发 + 消费」必须在**同一条命令内**完成，并在建立前清理同端口残留。
6. **`hdc` 的参数会被 Git-Bash 改写**：`/data/...` 之类的设备路径可能被 MSYS 转换；`hdc file send <本地绝对路径>` 会被拼成 `<cwd>/C:/...` 而报 no such file。可靠做法：① 设备侧路径前加 `MSYS_NO_PATHCONV=1`；② 传文件改用 **base64 经 `hdc shell` 落地**（本轮即用此法，`md5sum` 校验一致）。
7. **`hdc` 偶发 `need connect-key` / `channel being established`**：几乎每次操作都可能命中，**所有 hdc 调用都必须带重试**（本轮统一用带重试的封装）。
8. **锁屏会阻断部署**：设备重启后若锁屏（本轮为**密码锁**），`aa start` 直接失败：`10106102 The device screen is locked during the application launch, unlock screen failed`；开发者模式下无法自动解锁。`power-shell wakeup` 在 shell 域被拒、`uitest uiInput` 也无法越过密码。**部署前先确认屏幕已解锁。**
9. **审计用的一次性观测**：本轮开发过程中，一次多进程探针运行后应用进程被替换（`25334` → `26601`，15:55 前后）。**未能定位触发点**：无 faultlog、无 OOM/被杀记录，hilog 中同期只有 `F LIBUV: errno:13, sig_lock_pfd`（该行在正常运行时也周期性出现，属噪声）以及用户点击更新提示后的 `GetJSFunction ExternalWeb.Open failed`。**单次与连续两次 `spawn` 复测均不触发**。诚实标注为**未定**，列入 §B #2。

### C.5 `fork`/`exec` 与由此导出的设计约束

| 观测 | 结果 |
|---|---|
| `spawn('/system/bin/sh', ...)` | ✅ 命令执行，stdout/stderr 正常收回 |
| 子进程身份 | `uid=20020215(pci) gid=20215(pci_a20215) … context=u:r:debug_hap:s0`（**应用身份**，非 shell 身份） |
| `exit` / `close` / `error` 事件 | ❌ 6 s 内**全部缺席**；`exitCode` / `signalCode` 恒 `null` |
| 子进程终态 | `Z`（僵尸），长期不回收 |
| `spawn` 探针 `/data/service/hnp/bin/node` | `-v` → `v24.13.0`；`-e 'console.log(1+1)'` → **无输出** + `Z` |

**由此导出两条不可违反的设计约束**：

1. **宿主自身绝不 spawn**（本工程已遵守：Next 服务器进程内嵌，宿主零子进程）。这是规避「`exit` 不可观测 + 每 spawn 泄漏僵尸 + 子进程 JIT 被拦」的唯一低成本方式。
2. **面向用户的 `bash` 工具必须换实现或加兜底**（当前不满足）：pi 的 `waitForChildProcess()` 无轮询、无截止时间；`bash.ts` 的 `timeout` 判定在 await 之后 → 一次 `bash` 调用会挂住整个会话。见 §B #1。

### C.6 上游补丁链

**本版本补丁集为 0 条**（`patches/` 下无补丁文件，`patches/v0.11.1/` 目录不建）。8 个候选逐条源码核实见 `patches/README.md` §v0.11.1 基线复核；本轮真机复核进一步确认：Host 围栏天然放行（#24 全部 200）、无需任何头改写、写路径不依赖 symlink、`chmod` 假设成立（#13）。→ **上游升级时只需逐条复核那 8 条候选的文件路径，不需要重跑构建来「试出」补丁。**

### C.7 文件围栏（与参考工程的关键分歧）

pi 的文件审批流是**工具层**的（`read`/`write`/`edit` 走围栏）。但 **`bash` 子进程以应用 uid 运行**，按定义**绕过**该围栏 —— 与参考工程结论一致。本工程的处置是**技能层显式告知**（`skills/harmony-runtime-capabilities/SKILL.md` 写明「`bash` 无围栏、优先用 read/write/edit」），**属于最佳努力，不是沙箱**。若要真围栏，需要壳扩展在 exec 层做路径白名单。→ **L4，未处置。**

### C.8 二进制证书 / 自有 ELF

本工程**不随包分发自有 ELF**、不使用 HNP，因此**不需要二进制证书**（AGC `certType: 4`）与 `ALLOW_EXTERNAL_NATIVE_CODE`。运行时 `.so` 来自上游 Electron-on-鸿蒙运行时归档，属「消费上游产物」。→ **N/A**。上架只需 ACL 受限权限 `ohos.permission.kernel.ALLOW_WRITABLE_CODE_MEMORY`（`docs/工程规划.md` §11.4/§11.5）。

### D.2 平台事实（本轮核实，1–17）

1. 应用进程 uid/gid `20020215`，SELinux 域 `u:r:debug_hap:s0`（debug 构建；release 签名包不可侧载，见 `README.md`）。
2. 应用进程拓扑：主进程 + `:NetworkService` + `:GPU` + `:Renderer`（Chromium 多进程），全部同一 uid。
3. 应用沙箱根 `/data/storage/el2/base/files` 为 **`hmfs`**；用户目录卷为 **`hmdfs`**；两者 `chmod`/硬链接语义**不同**（见 §C.2）。
4. `hdc shell`（`u:r:sh:s0`）**看不到**应用沙箱与 `/data/service/hnp`（`Permission denied`）。
5. shell 域 `ln -s` 与 `ln`（硬链接）**都被拒**（`Permission denied`）；`chmod 640` 如实生效。
6. shell 域对**单条目** `lstat` 被拒 → `[ -L ]` 恒假、`ls -l <单条>` 报 `Permission denied`，但**目录列表可读**、`readlink` 可读。
7. `uname -a` 尾部 `Toybox` 是内核 utsname 字段，**不是** shell 身份；`/proc/self/exe` 之类探针同样不可信。
8. 设备可访问公网（`toybox wget http://api.deepseek.com` → `401`）；应用域内可完成真实模型调用（#24）。
9. 服务端监听 `0.0.0.0:<随机端口>`，渲染层经**局域网 IP** 访问（`PI_WEB_HOSTNAME=192.168.137.31`）；Host 围栏对 IP 字面量放行，**无需头改写**。
10. `PI_WEB_PASSWORD` 每启随机（43 字符）；Basic 用户名固定 `pi`（`pi-web/lib/web-auth.ts`）。
11. `PI_OFFLINE=1` 默认开启 → pi 永不尝试下载外部二进制/包（#18/#19/#20 的直接原因）。
12. 设备重启后应用**不自启**；且**锁屏会阻断 `aa start`**（密码锁下无法自动解锁）。
13. `/data/local/tmp` 在设备重启后**仍持久**。
14. `uitest uiInput`（`keyEvent` / `swipe` / `text` / `dumpLayout` / `screenCap`）在 shell 域可用 → 是**交互注入与 UI 文本取证**的可用通道；`text` 只能在已聚焦处输入，**无法输入密码锁屏**。
15. `snapshot_display` 可出图但拍不到 GPU 合成面（轮次 1 结论）；`uitest dumpLayout` 直接给 UI 文本，是更优判据。
16. Node 运行时 `22.17.0`（Electron 37 内置）；`process.getBuiltinModule('node:fs')` 在 CDP 上下文可用（`require` 不在默认上下文）→ **应用域取证的可用入口**。
17. 出网 / 硬件 I²C / 内核模块类 toybox 小程序（`insmod`/`lsmod`/`iptables*` 等）属系统级，本轮**未使用**（不在应用能力面内）。
